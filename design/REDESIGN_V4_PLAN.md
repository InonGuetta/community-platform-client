## כללי ריצה – מחליפים את "עצור והמתן לאישור"

1. **ענף:** `redesign-v4` בריפו הקליינט. כל שלב הוא commit אחד או יותר: `Redesign v4 stage N: ...`. אחרי commit מותר push של הענף. אסור force-push, ואסור לגעת ב-`main`.
2. **שער לפני commit:** `npm run verify` בקליינט ירוק. אם הלוגיקה זזה (נגן, ניווט, ⋯), גם `npm run e2e` (דורש API ו-Vite רצים, ראו הסקילים `run-server` ו-`run-client`). קוד שלא עובר את השער לא נכנס ל-commit.
3. **בדיקה שנשברה** כי היא בדקה את המבנה הישן (טקסט, label, מבנה DOM) – מעדכנים אותה כך שתבדוק את אותה התנהגות במבנה החדש. בדיקה שנשברה כי **התנהגות** נשברה – מתקנים את הקוד, לא את הבדיקה.
4. **החלטה שהמפרט לא מכסה:** בוחרים באפשרות ששומרת על כל פונקציה קיימת ומשנה הכי מעט. רושמים ב-DECISIONS. לא עוצרים.
5. **חסימה אמיתית** (משהו שאי אפשר להחליט עליו בלי אינון, או שער שלא עובר אחרי ניסיונות סבירים): לא עושים commit לחצי עבודה. מחזירים `BLOCKED` עם הסיבה, והמתזמר מחליט.
6. **i18n:** כל מחרוזת חדשה דרך הסקיל `add-translation`, בכל 5 השפות. Yiddish מסומן `_draft` כרגיל.
7. **כללי הפרויקט** ב-`CLAUDE.md` בתוקף: `sx` בלבד, ריווח לוגי (`marginInlineStart` וכו', לא `ms`/`me`), אין `react-redux` ב-`.jsx`, אין טקסט ישיר ב-JSX, הוק לכל לוגיקה.
8. **סקילים:** מי שמוסיף סקריפט ל-`package.json` מעדכן באותו שלב את הסקיל שמזכיר אותו (`run-tests`, `build-client` וכו') ורושם זאת ב-LOG.
9. **בסוף כל שלב:** רשומה ב-LOG, ואז החזרה למתזמר: `DONE` / `BLOCKED`, hash של ה-commit, ו-5 שורות לכל היותר.
